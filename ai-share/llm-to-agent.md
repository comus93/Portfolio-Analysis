## Context

사용자가 `feat/korean-market-v1`의 로컬 UAT를 진행했고, 1차 개선사항을 확정했다.

이번 작업은 **AS-IS 구조와 기존 구현을 최대한 재사용하고 최소 변경으로 처리**한다. 아래 요구사항을 위해 불필요한 리팩터링, 신규 데이터 모델/별도 맵 등의 구조를 선제적으로 만들지 말고 현재 코드 흐름에 맞춰 구현할 것.

## Message

다음 UAT 개선사항을 반영해줘.

### 1. Market Data Provider 선택 숨김

- 현재 사용자 UI의 `Market data provider` 선택 UI를 숨긴다.
- 현재 기본 market/provider는 **Korea (FinanceDataReader)로 고정**한다.
- provider 선택 기능 자체는 향후 별도 Settings UI에서 관리할 예정이므로 이번 범위에서는 Settings 화면을 만들지 않는다.

### 2. 포트폴리오 종목 검색/추가 UX 단순화

현재의 `검색 결과 표 → 별도 Drop-down → 선택 확정` 흐름을 다음으로 바꾼다.

1. 종목코드 또는 종목명 입력
2. 검색
3. 검색 결과 표에서 **단일 행을 직접 선택**
4. 선택된 행은 사용자가 알 수 있게 강조
5. `[추가]` 버튼을 눌러 포트폴리오에 추가
6. 추가 성공 후 검색어와 검색 결과를 초기화하여 다음 종목 검색 상태로 복귀

추가 요구:

- 기존 검색 결과용 Drop-down과 `[선택 확정]` 단계는 제거한다.
- 검색 결과의 첫 행 자동 선택/자동 추가는 금지한다.
- 이미 추가된 종목은 중복 추가하지 않는다.
- 종목코드/종목명 입력창에서 **Enter 키를 눌러도 검색이 실행**되어야 한다. 검색 버튼은 유지 가능하다.

### 3. 분석은 자동 계산이 아니라 수동 실행

- 포트폴리오 종목 추가/삭제, 비중 변경, 기간 변경 등의 입력 단계에서 분석을 자동 실행/재계산하지 않는다.
- 사용자가 전체 포트폴리오 구성을 마친 뒤 명시적인 **`[분석]` 버튼**을 눌렀을 때 데이터 로딩과 분석을 실행한다.
- 별도의 `분석 필요` 상태 안내 UI는 추가하지 않는다.

### 4. Benchmark UI는 독립 영역으로 유지하되 동일 검색 UX 적용

- Benchmark 검색/구성 UI는 포트폴리오 구성 UI와 **별도 독립 영역**으로 유지한다.
- 현재처럼 expander 등으로 화면 점유를 최소화할 수 있는 구성은 유지한다.
- 검색/선택 UX는 포트폴리오와 동일하게 `검색 → 결과 표에서 단일 행 선택/강조 → [추가]`로 통일한다.
- Enter 검색 및 추가 후 검색어/결과 초기화도 동일하게 적용한다.

### 5. Benchmark를 단일 종목이 아닌 포트폴리오로 확장

Benchmark도 사용자 분석 포트폴리오와 같은 방식으로 여러 종목을 구성할 수 있어야 한다.

- 여러 종목 추가 가능
- 각 종목 비중(%) 직접 입력
- 종목 삭제 가능
- `[추가]` 버튼 사용
- Benchmark가 구성된 경우 `[분석]` 실행 시 비중 합계가 100%인지 검증
- Benchmark를 구성하지 않은 경우에는 Benchmark 비교 없이 나머지 분석을 정상 수행
- 1개 종목 Benchmark도 동일 규칙으로 100% 비중을 사용

기존 단일 `benchmark_ticker` 중심 구현은 AS-IS 분석 구조를 최대한 활용하면서 필요한 범위에서 확장한다.

### 6. 6자리 코드 빠른 입력 모드에서도 종목명 표시

- 6자리 코드 빠른 입력 모드로 분석했을 때 차트/위젯/레전드가 코드만 표시하지 말고 **`코드 + 종목명`**을 표시하도록 한다.
- 종목명은 각 위젯 렌더링 때마다 별도로 조회하지 않는다.
- 분석을 위한 데이터 준비 단계에서 기존 종목 메타데이터 조회/보유 흐름을 최대한 활용하여 종목명까지 준비하고, 이후 차트/표/레전드에서 그 정보를 재사용한다.
- 이 요구를 위해 별도 신규 맵이나 새로운 데이터 모델을 임의로 만들지 말고 현재 구조를 우선 재사용한다.
- 종목명 조회 실패 시 코드 단독 표시는 fallback으로 허용한다.
